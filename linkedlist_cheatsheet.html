🏷️ Basic Notation

FIRST
Pointer to first data node of the linked list (NULL if empty)
AVAIL
Top pointer of the Availability Stack (Free Storage Pool)
INFO(P)
Data / information field of memory node at address P
LINK(P)
Pointer field containing address of successor node in SLL / CSLL
LPTR / RPTR
Left & Right pointers in Doubly Linked List (DLL / CDLL)
NULL (Λ)
Terminal ground indicator (End of list or empty link)
NEW
Pointer to freshly allocated node popped from AVAIL stack
TEMP / SAVE
Auxiliary traversal pointers for scanning without losing FIRST
PRED
Predecessor pointer tracking node immediately before current node
X
Data value / element to be inserted, deleted, or searched
SEARCH / M
Target key value (SEARCH) or target node address (M)
LAST / HEAD
Tail pointer in CSLL / Sentinel header node in CDLL

🏛️ Academic Memory Framework & The Availability Stack (AVAIL)

1. The Availability Stack (AVAIL)

In textbook computer science (Tremblay & Sorenson), heap memory allocation is modeled using an Availability Stack, a linked list of free, unallocated nodes headed by pointer AVAIL.

If AVAIL = NULL Then "Availability Stack Underflow"
NEW ← AVAIL; AVAIL ← LINK(AVAIL)

2. Node Memory Anatomy

Every node resides at a distinct memory address. In a Singly Linked List:

  • INFO(P) stores the payload data element $X$.
  • LINK(P) stores the address of the successor node (or NULL).
  • In DLL: LPTR(P) points to predecessor, RPTR(P) to successor.

3. Copy List Operation

To clone a list, we cannot simply copy pointer addresses (shallow copy). We must traverse the source list node by node, request a fresh node from AVAIL, copy INFO, and preserve relative linkages.

💡 Academic Analysis: INSERT_BEFORE vs INSERT_AFTER (Tremblay & Sorenson)
1. Why INSERT_BEFORE Requires Predecessor Search:

In a Singly Linked List, pointers are strictly forward-oriented. To insert before target node $M$ or value SEARCH, the link of the preceding node (TEMP where LINK(TEMP) = M) must be updated. This always incurs $O(n)$ search traversal from FIRST.

2. The Doubly Linked List (DLL) Advantage:

In a Doubly Linked List, every node maintains an LPTR backward pointer. Hence, the predecessor of $M$ is directly accessed via LPTR(M) in $O(1)$ constant time without any traversal loop!

3. INFO-Based vs Address-Based Insertion:

INSERT_BEFORE_INFO inspects node payload data (INFO(LINK(TEMP)) = SEARCH) and inserts before the first occurrence. INSERT_BEFORE_ADDRESS (classic INSBEF) inspects the actual memory address (LINK(TEMP) = M), guaranteeing insertion at the exact target location.
