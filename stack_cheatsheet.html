📚 1. Core Stack Operations & Algorithms

A Stack is a linear data structure that operates strictly on the LIFO (Last In, First Out) principle. The pointer TOP indicates the index of the topmost element. When the stack is initialized, TOP = -1 (empty).

1. PUSH(S, TOP, N, X) Insert

Inserts a new element X onto the top of stack S of max size N. First verifies that the stack is not full to prevent Stack Overflow.

[Check for Stack Overflow]
If TOP >= N - 1
    Then write "STACK OVERFLOW"
    Return
[Increment TOP]
TOP ← TOP + 1
[Insert Element]
S[TOP] ← X
[Finished]
Return

2. POP(S, TOP) Delete

Removes and returns the topmost element X. First checks if the stack is already empty (TOP = -1) to prevent Stack Underflow.

[Check for Stack Underflow]
If TOP = -1
    Then write "STACK UNDERFLOW"
    Return
[Retrieve Element]
X ← S[TOP]
[Decrement TOP]
TOP ← TOP - 1
[Finished]
Return X

3. PEEP(S, TOP, I) Inspect Depth

Views an element at depth I from the top without deleting it (I = 1 is top, I = 2 is one below). Checks if TOP - I + 1 < 0.

[Check for Invalid Index]
If TOP - I + 1 < 0
    Then write "INVALID INDEX"
    Return
[Access Element]
X ← S[TOP - I + 1]
[Finished]
Return X

4. CHANGE(S, TOP, I, VALUE) Modify

Updates an existing element at depth I from the top with a new VALUE without disturbing the rest of the stack elements.

[Check for Invalid Index]
If TOP - I + 1 < 0
    Then write "INVALID INDEX"
    Return
[Update Element]
S[TOP - I + 1] ← VALUE
[Finished]
Return

5. PEEK(S, TOP) View Top

Quickly accesses the current topmost element S[TOP] without removing it. If TOP = -1, reports underflow.

[Check for Underflow]
If TOP = -1
    Then write "STACK UNDERFLOW"
    Return
[Access Top Element]
X ← S[TOP]
[Finished]
Return X

🧮 3. Solving Expressions Using Stack (Notations & Parsing)

An arithmetic expression can be written in three different but equivalent notations without changing its result:

1. Infix Notation

Operators are written between operands (e.g. a + b or (a + b) * c). Natural for humans to read, but difficult and costly for computers to evaluate directly due to parenthesis and precedence rules.

2. Prefix (Polish) Notation

Operators are placed ahead of operands (e.g. + a b or * + a b c). Invented by Polish logician Jan Łukasiewicz. Evaluated by scanning right to left.

3. Postfix (Reverse-Polish) Notation

Operators are placed after operands (e.g. a b + or a b + c *). Eliminates all parentheses entirely! Computers can evaluate postfix expressions in a single pass using a simple Stack.
